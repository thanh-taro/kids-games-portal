# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

"Cứu Công Chúa" — a 2D pixel-art typing game that teaches kids Vietnamese **Telex** input. A hero fights through stages of monsters by typing the Vietnamese word floating above each one. Zero dependencies: plain HTML5 + Canvas 2D + vanilla JS ES modules. No build step, no frameworks, no image/audio assets — every sprite, scene, effect, and sound is generated in code.

**The story is a three-chapter saga over 26 stages** (see `story.js` / `chapters.js`), following a prologue: the **Demon King, the World Devourer**, has kidnapped ten princesses, each a guardian of the world's balance.
1. **Lời Thỉnh Cầu Của Đức Vua** (The King's Request), stages 1–12 — two warm-ups plus the ten princess rescues.
2. **Trượng Của Trí Tuệ** (The Staff of Wisdom), stages 13–20 — courage alone is not enough; a quest for the artifact that can wound the Demon King.
3. **Trận Chiến Cuối Cùng** (The Final Confrontation), stages 21–26 — storm the fortress and defeat the World Devourer for good.

**Everything serves the typing practice.** When a design choice trades off against typing legibility or practice value, legibility wins — the word above a monster must always be readable and on screen, and scenery must never out-read an enemy (both were real bugs; see the notes on `CREEP_BOOK` and `drawTargetWord`).

## Commands

```bash
python3 serve.py 8177          # dev server — ALWAYS use this, not `python3 -m http.server`
node js/telex.test.js          # Telex engine tests + round-trips EVERY word pool
node js/verify.js              # data-invariant checks (sprites, stages, chapters, rewards)
```

- **`serve.py` is a no-cache dev server.** Plain `http.server` makes Chrome aggressively cache ES modules, so edits to `js/*.js` silently don't reload and you end up testing stale code. Always serve via `serve.py`.
- There is no lint/build. `node --check js/<file>.js` syntax-checks a module. `/check` runs all three passes.
- Open `http://localhost:8177/index.html`. ES modules require HTTP (not `file://`).

**Run both test scripts after ANY content change.** They exist because this game's data is hand-authored and its failure modes are invisible in review:
- `telex.test.js` types every `WORD_POOLS` entry through the real engine and asserts it renders exactly its `vi` string, *and* rejects mid-syllable tone keys (the convention is tone key last: `truwngs`, not `truwsng`). Adding ~150 words in one sitting produced 6 wrong hints that only this caught.
- `verify.js` asserts sprite frame geometry + palette chars, that every stage's biome exists in **both** `biomes.js` and `monsters.js`, that every wave's pool/skill resolves, that `CHAPTERS` ranges **tile `STAGES` exactly**, and that `REWARDS` covers every stage (`rewardForStage` wraps modulo, so a short list silently re-grants early gear — a live bug it found).

## Testing in the browser (claude-in-chrome)

Gotchas that will waste time if forgotten:
1. **Canvas focus:** after a navigate/reload the canvas does NOT have keyboard focus — `type` keystrokes are dropped silently. Always `left_click` the canvas once before typing.
2. **Synthetic typing may not reach the game.** The MCP `type` action can be swallowed entirely. Dispatching events directly is reliable: `window.dispatchEvent(new KeyboardEvent('keydown', {key: ch, code: ch === ' ' ? 'Space' : 'Key'+ch.toUpperCase(), bubbles: true}))`.
3. **Stale screenshots:** effects and impacts last only a few frames; a single screenshot often lands between frames. Burst 3-5 screenshots, or confirm true state via `__debug.info()` (below) rather than a lone screenshot.
4. **Screenshots are scaled down** (e.g. a 1800px canvas arrives as 1568px), so content near the right edge can look cut off when it actually fits. Verify edge-clamping by computing coordinates in the page, not by eye.

**`window.__debug` (localhost only, defined at the bottom of `main.js`)** is how you reach a late scene without playing ~500 words to it: `goStage(i)`, `setState(NAME)`, `story(chapterId, 'opening'|'closing')`, `lastWave()` (jump to a stage's final wave), `chargeStaff()`, `atChapterFinale(i)` (the exact post-victory state at a chapter boundary), and `info()` (state, stage, chapter, wave, monster phase/shield/word, staff charge). It is inert on any non-localhost host and only ever writes state.

To showcase or tune fast visual effects, write a throwaway `effects-preview.html` at the repo root that imports the modules and fires effects on a loop (URL `#hash` to pick one), screenshot it, then delete it.

## Architecture

Entry point is `js/main.js` (loaded as a module from `index.html`). The game is a **canvas render loop driving a state machine**; there is no DOM UI — everything is drawn on one `<canvas>`.

**State machine (`main.js`):**

```
TITLE ─→ STORY(prologue + ch.1 opening) ─→ TUTORIAL ─→ STAGE_INTRO → PLAYING
              (first play only; ESC skips)
PLAYING → VICTORY → REWARD ─┬─ mid-chapter ──────→ STAGE_INTRO (next stage)
                            └─ chapter finale ──→ CHAPTER_END → STORY(closing)
                                                     ├─ more chapters → STORY(next opening) → STAGE_INTRO
                                                     └─ final chapter → GAME_COMPLETE → CREDITS → TITLE
PLAYING → FAILURE → retry same stage
```

`SPACE` advances scenes; `H` on the title opens the tutorial, `S` replays the current chapter's story, `R` resets progress; `F9` toggles mute (a function key, because every letter is a real Telex typing character and `ESC` is the tutorial's *and* the story's skip key — F9 is handled before both branches so it works in every state, and `drawMuteHint()` draws the guide in every scene from `loop()`). During `PLAYING`, `main.js` runs `updatePlaying()` + `renderPlaying()`; other states delegate to `scenes.js` draw functions. Note: `updatePlaying()` can transition state mid-frame, so it re-checks `state` before rendering.

**The story layer.** `story.js` is pure data: `PROLOGUE`, `CHAPTER_STORY` (per-chapter `opening`/`closing` page lists), and `CREDITS`. A page is `{art, lines}`; `art` names a tableau drawn by `drawStoryArt` in `scenes.js` (`throne`, `kidnap`, `road`, `library`, `staff`, `fortress`, `duel`, `peace`, `crown`). `main.js` holds a small queue `{pages, page, title, after}` where **`after` names where the narration hands off** — `'tutorial' | 'stage' | 'nextchapter' | 'ending' | 'title'`. `finishStory(after)` is called both when the pages run out **and on ESC**, so skipping always lands exactly where reading would have (a story that stranded the player on skip would be worse than no story). `progress.seenStory` (an array of chapter ids) persists so narration replays only when new.

Two ordering decisions worth keeping: the **prologue plays before the tutorial** (the King gives the mission, *then* the hero learns the craft — a Telex lesson with no context is what the old flow did), and the **tutorial's first lesson is written in the King's voice** to match, so the two read as one sequence rather than a manual bolted onto a story.

**The Telex engine (`telex.js`) is the educational core** — treat it as the highest-risk module. It converts raw ASCII keystrokes to Vietnamese exactly like a real Telex IME. Buffer is an array of atoms (vowel atoms hold base+tone+shape, consonant atoms hold a char). Key exports: `newBuffer()`, `applyKey(buffer, key)` (returns a NEW buffer), `render(buffer)`, `typeString(raw)`. The trickiest logic is `findToneTargetIndex` (tone placement) — it operates **only within the current syllable** (the run after the last space atom) to stop tones bleeding across words in phrases/sentences. **Add a case to `telex.test.js` before touching tone/shape logic**, then `node js/telex.test.js`.

**Typing → combat flow:**
- `input.js` `TypingTracker` feeds each keydown through `telex.applyKey`, tracks prefix-match against the target word, and fires `onProgress(matchedLen, mistake)` / `onComplete()` callbacks (set in `main.js`). `attachKeyboard(tracker)` wires the global keydown listener. SPACE during `PLAYING` is a real typing char (phrases contain spaces) — `main.js` guards against treating it as a menu confirm.
- On `onComplete`, `main.js` spawns the monster's skill projectile(s). A multi-projectile volley marks only `proj.isLeadHit` so a 3-shot fireball still counts as one hit.
- `onProjectileHit` (in `main.js`) applies the hit: monster `reactToHit()` (flash+knockback), `particles.play(skill.effect,...)`, register the hit, and on defeat `particles.death(...)`.

**Entities (`entities.js`):** `Hero`, `Monster` (three `MONSTER_KIND`s: CREEP marches to contact; BOSS/STAGEBOSS are `stationary`, hold at `standGap`, and attack the hero on a timer via `takeAttack()`), and `Projectile`. Monsters take `hitsNeeded` completed words to kill; bosses call `assignBossWord()` to present a fresh word after each surviving hit.

**Two mechanics added for chapters 2–3:**

- **The Staff of Wisdom** (`hero.hasStaff` / `staffCharge`, granted by the `artifact`-type reward at stage 20). Each **cleanly** typed word adds a charge; at `STAFF_CHARGE_FULL` (5) the next completed word fires an **empowered** strike (`proj.empowered`) — bigger, gold-white, +3 hit-points of damage. Charging on *clean* words specifically is the point: the artifact rewards accuracy, not speed, which is the skill the game teaches. `drawStaffMeter()` shows the pips under the combo meter.
- **Multi-phase bosses** (`Monster.phases`, used by stage 26's World Devourer). A wave may carry `phases: [{name, hits, shielded?, attackEvery?, attackDamage?}]`; running a phase's bar to zero **advances** instead of killing, and `registerHit()` returns `'phase' | 'dead' | ''` so `main.js` plays the right flourish. `isDefeated` is `hitsLeft === 0 && !hasNextPhase`, which is what stops the combo-multiplier damage loop from over-killing through several phases in one landing. A `shielded` phase takes **no** damage from an ordinary hit — only a charged-Staff strike pierces it, which is the mechanical payoff of the whole chapter-2 quest. `drawShieldHint()` says so on its own fixed row (a kid seeing attacks do nothing otherwise concludes the game is broken).

**Data-driven content:**
- `stages.js` — `STAGES[]`: each stage has name, princess (+ `princessStyle`, her look — see `princessSprite` under Sprites), intro text, a `biome` (its scene theme — see `biomes.js`), and a `waves[]` list of `{type, pool, skill}` (a stageboss wave may add `phases` — see Entities). Curriculum ramps letters → words → phrases → sentences → long sentences → proverbs. `getStage(i)`, `TOTAL_STAGES`. There are **26 stages across 3 chapters**; adding more is pure data (append to `STAGES`, then update `CHAPTERS`).
  Chapters 2–3 have **no princesses** (all ten are rescued in chapter 1) — the scenes render the "practice/goal" variant instead. Their difficulty comes from the WORDS, not longer gauntlets, so wave counts hold at ~16–20 rather than climbing further.
- `chapters.js` — `CHAPTERS[]`: story chapters that group `STAGES[]` by RANGE (`stageStart` + `stageCount`) over the single flat stage list, so the stage/reward/progress machinery (one 0-based `stageIndex`) is untouched — chapters are a presentation grouping. Helpers: `chapterForStage`, `stageNumberInChapter`, `isChapterFinale`, `isChapterStart`, `nextChapter`, `isFinalChapter`. Title/stage-intro/HUD show the chapter.
  **The ranges must tile `STAGES` exactly** — no gap, no overlap, ending at `STAGES.length`. Counts are written out literally rather than derived from `STAGES.length` so that adding a stage to the wrong chapter *fails* `verify.js` instead of being silently absorbed; `chapterForStage` falls back to the last chapter rather than throwing, so a gap would otherwise show up only as a wrong on-screen label. To add a chapter 4: append its stages, add its `CHAPTERS` entry, and add its `opening`/`closing` to `CHAPTER_STORY` in `story.js`.
- `biomes.js` — `BIOMES`: **each stage's backdrop matches its name AND carries its story meaning**, in a bright storybook-fantasy style. Each biome's comment states the MEANING it carries; **preserve that when editing**. The through-line runs across all three chapters and is the main thing to keep intact:
  - **Chapter 1 (1–12):** the villain's `SPIRE` sits in every biome's `far` layers and grows nearer stage by stage (a speck in stage 1 → flanking towers filling the sky in stage 12). Several stages carry a small *trace* prop left by the princess taken from there (dropped flower crown, broken cage, message bottle, frozen tear), so 12 backdrops read as one chase.
  - **Chapter 2 (13–20) inverts it:** the hero has deliberately turned away from the spire, so the black `SPIRE` **recedes** to the far left edge while the pale, round-topped `WISDOM_TOWER` grows in its place — two towers on the horizon, one shrinking and one growing. The chapter also lightens overall (dim ruined library → sunlit summit), the opposite of chapter 1's slide into darkness.
  - **Chapter 3 (21–26) resolves it:** the hero turns back with the Staff, so the spire grows again, faster and larger, until stage 26's landmark is `SPIRE_CROWN` — the tower's own broken top. The last backdrop of the game is the first backdrop's distant speck, now underfoot.
  Layer order, back to front: `sky` → `far` → `horizon` → `band` → `ground` → `body`/`clouds`/`flyers` → `ceiling` → `landmark` → `props` → *(entities, drawn by `main.js`)* → `tint` → `lights` → `weather`. Draw entry points are split so entities land mid-stack: `drawBiomeTerrain` / `drawBiomeScenery` / `drawBiomeLights` / `drawBiomeWeather`, or `drawBiomeScene` for all of it at once (used by the menu scenes).
  `landmark` is the ONE big set piece per stage (spirit tree, bone arch, shipwreck, colossal hand, frozen fall, lava fall, castle gate, the Tower of Wisdom, the Staff, the Demon King's throne, the spire's broken crown); `lights` is an **additive** pass — `'rays'` god rays, `'aurora'` curtains, `'glow'` radial pools, `'shimmer'` heat haze, `'beam'` a single vertical pillar anchored to a thing on the ground (the Tower's beacon, the void rifts) — and is what keeps a big sky from reading as a flat slab.
  Weather kinds: `rain`, `snow`, `embers`, `fireflies`, `petals`, `sandstorm`, `drip`, `mist`, `surf`, plus `starfall` (mostly-twinkling motes; every fifth one streaks), `leaves` (tumbling pages that drift sideways faster than they fall), `ash` (slower than snow, drifting to one side), and `voidmotes` (**rises** instead of falling — nothing else in the game moves upward, so that one detail tells a kid they have left the world behind).
  Four invariants when authoring a biome: **`band` is the strip entities walk on** so it must be solid footing (use `horizon` for distant water — that's why `coast` puts the sea *behind* the beach); **grounded props and the sky `body` stay clear of the hero's spawn** (roughly the left 0.18 of the width); **watch the units** — `at` is a fraction of width, prop/glow `lift` is a fraction of ground height, while `body.y` and `baseOffset` are absolute px; and **scenery must not out-read the monsters** — `library`'s multicoloured bookshelves were initially the brightest thing on screen and the book creep vanished against them, so they are now `tint`ed down and pushed to the edges. A new biome is a new `BIOMES` entry; a genuinely new look is one more case in `drawBiomeWeather` or `drawBiomeLights`.
- `skills.js` — `SKILLS` each carry damage, `projectile`, `burst`, `effect` (name dispatched to `particles.play`), and `trail` config. Chapter 1: `slash`/`fireball`/`lightning`/`meteor`. Chapter 2 (precision and control, matching its "a clear mind beats brute force" theme): `frostnova`, `windblade` (the fastest, five-shot volley — it *looks* like speed), `holylight`. Chapter 3: `voidrend`, `dawnbreaker` (the Staff at full power, and the biggest effect in the game).
  `WORD_POOLS` by tier + `pickWord(pool, index)`; `SKILL_CLASS` simple vs special. `SPECIAL_ORDER` is the unlock ladder, and `resolveSkill(wantedId, unlocked)` walks **down** it to the best special the kid has actually earned, so a wave never fires an unearned ultimate on a fresh save.
  **The word tiers are the curriculum, and each exists for a specific Telex skill** (all seven are round-tripped through the engine by `telex.test.js`): `letters` (single vowels + tones) → `words` → `phrases` (a space between words, so tones stay inside their own syllable) → `sentences` → `hard_sentences` (5–8 syllables, tone-dense, shape keys that need doubling) → `long_sentences` (7–10 syllables where the tone changes on nearly every one — *sustaining* a clean run is the skill, and it is what actually breaks kids) → `wisdom_sayings` (real Vietnamese proverbs, 8–12 syllables, every tone in one line). The top tier is deliberately proverbs a Vietnamese child hears from grandparents, so the reward for the hardest typing in the game is a sentence worth having learned.
- `rewards.js` — `REWARDS[]`, one per stage (**26 entries**; `verify.js` asserts `REWARDS.length >= TOTAL_STAGES` because `rewardForStage` wraps modulo and a short list silently re-grants early gear). Types: `weapon` (stat boosts + a blade tint), `skill` (unlocks a special), and `artifact` — currently just the Staff of Wisdom, which carries stat boosts *and* switches on a mechanic. `rewardForStage`, `hasStaffOfWisdom`, and `localStorage` progress (`loadProgress`/`saveProgress`/`resetProgress`, key `ccc_progress_v1`; `loadProgress` back-fills fields missing from older saves, e.g. `seenStory`). `applyRewards(hero, ids)` equips stat-boosts, extra skills, and the Staff onto the hero.

**Rendering (`render.js`):** `DOT` is the master pixel-scale multiplier — **change `DOT` to resize the entire world at once** (currently 3, tuned for a wide-landscape look; entity `scale` values multiply it further). `drawSprite(ctx, sprite, frame, x, y, scale, flip, tint?)` — `tint` overrides all pixels with one color (used for the white hit-flash). `drawScene(ctx, w, h, groundY)` paints the original desert backdrop (sky/sand/layered dithered ground); per-stage themed backdrops live in `biomes.js` and are what the game actually draws.

**Sprites (`sprites.js`):** all art as arrays-of-strings dot grids; each char is a `PALETTE` key, space = transparent. Sprites use black outline `k` + base color + shade tone. `SPRITES` is the entity lookup — note that **chapters 2–3's entity sprites are `Object.assign`ed onto `SPRITES` at the BOTTOM of the file**, because their consts are defined below the literal and cannot be named inside it. ~60 scenery props are exported separately and referenced by `biomes.js` — `CLOUD/SUN/MOON/BIRD` (sky), `MOUNTAINS/SPIRE/WISDOM_TOWER` (far layers), flora & rocks, `STALAGMITE/STALACTITE/CRYSTAL` (cave), `JAIL/TOWER/CASTLE_GATE` (fortress), the story landmarks, the princess traces, and the chapter 2–3 props (`BOOKSHELF`, `WIND_PILLAR`, `MIRROR_STAND`, `STAR_TREE`, `BONE_PILLAR`, `CELL_DOOR`, `VOID_RIFT`, `DEMON_THRONE`, `SPIRE_CROWN`, `DEMON_BANNER`), plus the story-scene pieces `KING`, `THRONE`, `STAFF_WISDOM`.

`node js/verify.js` validates every sprite's geometry and palette chars — **run it after any sprite edit** instead of eyeballing the grids. (Rows may be padded PAST `w` with trailing spaces, which are transparent and harmless — `CREEP_SLIME` ships that way; what corrupts a sprite is visible content at/beyond column `w`, or a row that stops short mid-pattern, and those are what the check catches.)

**Monster legibility beats scenery detail.** Two creeps had to be redrawn because they were too small and too pale to find at gameplay scale — `CREEP_BOOK` (now 14x12, saturated crimson, solid body: a small sprite with a gap down its centre breaks into two shapes) and `CREEP_MIRROR` (now carries a dark-teal band down one whole face, so its silhouette has internal contrast and does not depend on a dark background). The rule that follows: a creep must read against its own biome without help, because the kid has to find the monster to read the word above it.

  **Faces are a trap at this pixel size:** a rounded outline with two even eye-blobs over a horizontal band reads as a cartoon smiley, not architecture. The buried statue went through two face designs before becoming a colossal *hand*, and `CASTLE_GATE` was deliberately made asymmetric (one off-centre lit window, diagonal chains) for the same reason. The same principle drove the chapter 2–3 bosses: `BOSS_GUARDIAN_STATUE` is built from architecture (square shoulders, a carved chest rune) rather than anatomy, `BOSS_FORMLESS` has three eyes at **uneven** heights (evenly spaced ones read as a face), and `STAGEBOSS_DEVOURER` puts its maw on the **torso** rather than the head — a mouth where a chest should be is what stops the final boss reading as a big cartoon face.

  **A monster needs one unmistakable prop.** Several chapter 2–3 bosses are read almost entirely from a single held object rather than their silhouette: the Ink Scribe's upright quill, the Jailer's lantern held out to one side, the Iron Warden's chest padlock, the Guardian's raised Staff (which also shows the kid the prize they are fighting for). A diagonal version of any of them reads as clutter — held objects run vertical.

  **The humanoids (hero + princesses) follow four hard-won rules** — the originals (14x16 hero, 12x16 princess) broke all of them and read as blobs:
  1. **Eyes are single DARK pixels on skin**, never white-on-black. A 4px-wide face has no room for sclera + pupil, so the old `kSWkSWSk` read as a black *nose stripe* between two white blobs. Monsters still use white `W` eyes — they're big enough.
  2. **Hair before hats.** A helmet/crown sitting straight on skin reads as a colored blob; the hair mass framing the face is what says "person". A crown's band must never sit directly on a black outline row either — they merge into one stripe.
  3. **A weapon must be HELD.** The hero's sword went through a version floating diagonally by his shoulder that read as a feather/party-hat plume. It reads as a sword because it's vertical, has a gold crossguard, and a raised arm connects fist to shoulder.
  4. **Idle frames move only the extremities.** Frame 2 of each may differ ONLY in cape (hero) or skirt hem (princess) pixels — an earlier hero shifted its whole torso down a row and read as *squatting*, and cape-widening silently ate torso pixels so the body jerked sideways. Verify with a diff that asserts every differing pixel is cape/hem-only.
  Skirt/cloth shading wants **contiguous 1px vertical drape lines** — scattered single shade pixels read as dirt specks, a solid 3px block reads as an apron or a hole.

  **`heroSprite(weaponColor)`** returns the hero with his blade tinted to the equipped weapon (from `rewards.applyRewards` → `hero.weaponColor`), so weapon rewards are visible. It caches per color, registering a private-use slot char pair into `PALETTE` on demand (`PALETTE` is one flat shared char→color map, so a per-instance blade color can't live in it directly). No weapon → the shared base sprite.
  **`princessSprite(styleName)`** builds one of the 10 princesses from ONE body template + a `PRINCESS_STYLES` entry (gown/hair/crown-accent palette keys + a `CROWNS` motif), remapping slot chars `G/g` gown, `A/a` hair, `C` crown-accent. Each stage names its own via `princessStyle` in `stages.js`; a stage without one falls back to the default purple gown. **A new princess is a new `PRINCESS_STYLES` entry (+ a `CROWNS` motif if she needs a new silhouette) — data, not a new hand-drawn sprite.** Crown bands are always gold: a band tinted to a pale theme color vanished into pale hair. `scenes.js` derives its ten-princess line-ups (`drawPrincessRow`, used by the `peace`/`kidnap`/`crown` tableaux and the Final Ending) from `STAGES`, so they can never drift out of sync with who the game actually has you rescue.
  **`KING`** is the second humanoid and obeys the same four rules. His hair uses the off-white `w`, **not** the hero's hair-brown `H`: at 16px an old king is read almost entirely from "white hair + white beard", and brown hair over a white beard read as a young man in costume.

**Effects (`effects.js`):** `ParticleSystem` holds `particles` + one-shot `visuals` + `screenShake`. `Particle` supports gravity (negative = rise), drag, `fadeTo` color blend, shrink. `Visual` kinds: shockwave, flash, bolt, slash, beam, burst. Signature per-skill effects via `play(effect, x, y, W, H)`; `death(x, y, color, tier)` for tiered kill explosions; `trailPuff(...)` for projectile comet trails. **New skill effect = a new case in `play()` + an `effect:` field on the skill.**
  The chapter 2–3 effects are deliberately differentiated by MOTION, not just color, since color alone is hard to tell apart mid-fight: `frostnova` shards hang (near-zero gravity) where fire debris falls; `holylight` motes **ascend**; `windblade` launches on a spiral so it curls rather than starbursts; `voidrend` first pulls motes **inward** from a ring before bursting out; `dawnbreaker` is a sunrise (twin pillars + three gold shockwaves) and is the biggest effect in the game. `phasechange` is a dark implosion into a rising column — read as "he is changing", explicitly not as `death`.

**Audio (`audio.js`):** all sound synthesized via Web Audio (oscillators/gain/noise). AudioContext is created lazily and must be resumed on a user gesture — `resumeAudio()` is called on first keydown in `main.js`. Event functions: `keyBlip/keyError`, `simpleAttack/specialAttack`, `hit`, `hurt`, `victory/failure/reward`, `confirm`, `comboMilestone/comboTierUp/comboBreak`, `rankUp`, and for the new mechanics `staffCharged`/`staffStrike`, `shieldBlock` (deliberately dull and muffled, so it reads as "that did nothing"), `phaseChange`, `storyPage` (very soft, so paging the prologue doesn't sound like a menu confirm); `toggleMute()/isMuted()`.

**Other modules:** `combo.js` (`Combo` — clean-word streak, tiers with damage multipliers, milestone banners), `rank.js` (`RankTracker` — lifetime accuracy + speed gates → `RANKS`, kill points, auras from Master up; gates are tuned to **measured kid typing**, and the long comment there explains why CPM understates real keypress speed in Telex), `monsters.js` (`BIOME_MONSTERS` — which monsters each biome fields, plus auto-derived `MONSTER_COLOR` death hues), `tutorial.js` (the interactive Telex lessons, which feed keystrokes through the real engine).

## Conventions

- All in-game text is Vietnamese (with an English gloss in a code comment). Keep the kid-friendly, encouraging tone.
- Reproducibility: avoid `Math.random()` at construction time in effects — use per-index variation or the seeded `rand()` helper in `effects.js`, so particle bursts look organic without nondeterminism.
- HUD/scene text over the bright sky is drawn on dark plates (`#1a1423`) with light text (`#fff4d6`) for legibility — follow that when adding UI.
- **Text that can be long must clamp to its own measured width, not a fixed margin.** The late word pools are whole proverbs; a target-word plate anchored to the monster with a fixed 110px clamp ran clean off the screen edge, which makes the game unplayable rather than merely ugly. `drawTargetWord` now centres any plate wider than 55% of the screen, and the boss bar / shield hint each clamp to their own content.
